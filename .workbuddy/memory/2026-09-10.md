## 追加3：AI 改写弹两次 toast + 文案太简（useAgent.ts 二次改造）

### 根因（两条路径各弹一次）
- `run()`：`POST /agent/:type/chat` 是**同步**的（后端 `backend/src/routes/agent.ts:46` 起，先插 sys_task=processing，跑完 agent 才返回 200），前端收到 200 就弹一次。
- `pollStatus()`：页面挂载时 `syncRewriteStatus()`（`episode.vue:2782`，onMounted 调用）若查到 task 仍是 processing 就起轮询，2.5s 一轮，轮询到 completed 再弹一次 → 用户看到两条。
- 之前只加了 `toast.success(msg, { id })` 去重**不够**：`app.vue` 的 Toaster duration 只有 3200ms，而改写要十几秒，两条 toast 间隔远超去重窗口，必须让旧轮询彻底失效。

### 本次改动（`frontend/app/composables/useAgent.ts` 已重写）
- 引入 **pollToken 世代号**：`invalidatePoll()` 递增 + clearTimeout；`pollStatus()` 每轮拿 token，`await` 醒来先 `alive()` 校验，旧轮询自行退出（clearTimeout 拦不住已经 in-flight 的 await）。
- `run()` 开头先 `invalidatePoll()` 并记下 token，结束后 `token !== pollToken` 就不弹提示、不覆盖 running 状态。
- 文案改为 **title + description**（vue-sonner 1.3.2 支持 `description`）：`AGENT_DONE_TEXT` 按 agent 类型给「做完了什么 / 下一步干什么」，并在耗时 ≥1s 时追加「耗时 N 秒」。
  - script_rewriter → 「AI 剧本改写完成 / 已生成格式化剧本，请核对内容后再进入资产制作」
  - extractor / storyboard_breaker / prompt_generator 各自有对应文案
- 错误提示统一走 `friendlyErrorMessage`（从 `./useFriendlyError` 引入），不再裸抛 axios/后端英文。

### 环境坑（更新旧笔记）
- **3013 的 502 不是 Docker 占端口**，是环境里的 `HTTP_PROXY=127.0.0.1:65029` 把请求代理走了 → curl 必须用 `--noproxy '*'`。
- Nuxt dev 只监听 `[::1]:3013`，用 `http://localhost:3013/` + `--noproxy` 才能通；普通 `&` 起的进程在 Bash 工具 turn 结束后会被杀，必须用 `run_in_background: true` 才常驻。
- 验证下发产物：`curl --noproxy '*' http://localhost:3013/_nuxt/composables/useAgent.ts`（**没有 app/ 前缀**），本次已 grep 到 `AI 剧本改写完成` / `pollToken` / `invalidatePoll` 确认生效。

## 追加3：dev server 无法由会话持久启动 → 必须用户自己终端跑

### 环境限制（重要，别再踩）
WorkBuddy 的 Bash 执行环境会在**每条命令结束时回收该命令派生的所有子进程**，已逐一验证：
1. `run_in_background: true` 任务 → turn 结束被回收（task_id 直接消失）
2. `nohup ... & disown` → 命令结束被杀
3. `launchctl bootstrap/load` LaunchAgent → 报错 5: Input/output error（环境隔离了 gui domain）
4. `osascript do shell script (nohup ... &)` → 能活到下一条命令（期间 curl 200），再下一条就死 —— 同样被收尸

- 会话 shell 有 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:50510`，curl 对 localhost 的 502/200 可能是代理返回的
- **测本地服务一律加 `--noproxy '*'`**
