# 万影工坊 SaaS 产品需求梳理

## 1. 需求概述

万影工坊当前是一个本地运行的 AI 短剧创作工具，用户需要在本地部署服务、配置数据库和 AI API，才能使用剧本、素材、分镜及视频生成能力。

本次改造的目标是将产品升级为在线 SaaS 平台：平台由管理员统一维护 AI 服务，用户通过账号登录使用创作功能，并使用积分兑换 AI 生成能力。用户可以自行充值，注册后获得一笔初始赠送积分。

一句话定义：

> 万影工坊是一个按积分使用 AI 能力的在线短剧内容生产平台。

## 2. 本次需求明确包含的内容

- 产品名称改为“万影工坊”。
- 从本地服务模式改为在线 SaaS 模式。
- 增加管理员后台。
- 管理员可以配置文本、图片、视频等 AI API 服务。
- 增加用户终端。
- 用户可以注册、登录和管理自己的账号。
- 用户使用积分生成 AI 内容。
- 计费单位为积分，兑换比例为 1 元 = 10 积分。
- 每个 AI 生成环节需要有独立价格。
- 用户在使用 AI 功能前可以看到价格和预计消耗。
- 用户可以自行充值购买积分。
- 新用户注册后获得一定数量的赠送积分。

## 3. 产品边界

### 3.1 用户端

用户端负责创作和消费：

- 管理账号。
- 创建和管理自己的短剧项目。
- 使用工作台完成短剧内容生产。
- 查看 AI 能力价格。
- 使用积分发起生成任务。
- 查看结果、任务状态和消费记录。
- 充值购买积分。

### 3.2 管理后台

管理后台负责平台运营和成本控制：

- 管理用户。
- 配置 AI 服务和模型。
- 设置 AI 功能价格。
- 管理充值订单和积分流水。
- 查看生成任务。
- 处理失败任务、退款和异常。
- 查看用户量、收入、AI 调用量和成本。

### 3.3 首版暂不包含

- 用户自行配置 API Key。
- 会员等级、订阅套餐和月度会员。
- 完整的商业发票系统。
- 用户之间的内容交易或社区功能。
- 内容审核、敏感词检测和版权投诉处理。
- 用户额度、IP 风控和异常注册识别。
- 邮件、短信和站内任务通知。
- 用户反馈、工单和运营活动。
- 精细化用户留存分群、广告投放归因、LTV 预测和完整财务毛利核算。

## 4. 现有产品改造范围

当前创作流程可以保留，主要增加 SaaS 能力。

| 现有模块 | 改造要求 |
|---|---|
| 项目管理 | 项目归属于个人工作区或企业团队空间，用户只能看到有权限的项目 |
| 剧本改写 | 增加价格展示、余额检查和积分扣费 |
| 角色/场景/道具提取 | 增加价格展示和任务计费 |
| 提示词生成 | 每种提示词能力独立计价 |
| 图片生成 | 按类型、模型、尺寸计费 |
| 分镜拆解 | 按次或按项目计费 |
| 视频提示词生成 | 可按分镜数量计费 |
| 视频生成 | 按模型、时长、分辨率计费 |
| 任务列表 | 增加用户归属、消费金额和退款状态 |
| 素材库 | 改为云端存储并按用户隔离 |
| 设置页 | AI API 配置迁移到管理员后台 |
| 本地文件目录 | 逐步迁移到对象存储 |
| 本地任务轮询 | 逐步改为持久化任务队列 |

## 5. 用户端需求

### 5.1 注册与登录

- 使用手机号注册。
- 使用手机号和密码登录。
- 通过手机号找回密码。
- 修改密码和退出登录。
- 查看账号状态。
- 注册后自动创建积分账户和默认工作区。

### 5.2 我的项目

- 创建、查看和编辑短剧项目。
- 注销项目时必须弹出二次确认。
- 确认注销后，项目、项目下的图片、视频、上传文件和其他素材全部永久删除且不可恢复。
- 下载自己生成的图片和视频，下载内容不添加水印并支持原始质量。
- 进入剧集创作工作台。
- 查看项目下的角色、场景、道具、分镜、图片和视频。
- 用户不能访问其他用户的项目、任务和文件。

### 5.3 团队与企业账号

用户可以创建或加入团队空间，企业账号以团队空间为核心管理项目、成员和积分。

- 创建团队空间。
- 邀请成员加入团队。
- 管理成员的加入和移除。
- 团队成员共同访问团队项目。
- 项目归属于团队空间，而不是某个个人账号。
- 团队管理员可以创建、编辑、删除和分配团队项目。
- 普通成员只能访问被授权的项目。
- 团队管理员可以查看团队任务、积分消费和充值记录。
- 企业账号使用团队共享积分账户。
- 个人账号和企业账号的数据、积分和权限相互隔离。

首版团队角色建议包括：

| 角色 | 权限 |
|---|---|
| 企业所有者 | 管理企业账号、成员、项目、积分和全部设置 |
| 团队管理员 | 管理成员、项目和团队任务 |
| 创作者 | 创建和编辑被授权项目，使用团队积分 |
| 查看者 | 查看项目和生成结果，不能发起 AI 生成 |

### 5.4 创作工作台

保留现有流程：

1. 输入或导入原始内容。
2. AI 改写为格式化剧本。
3. 提取角色、场景和道具。
4. 生成角色、场景和道具提示词。
5. 生成角色、场景和道具图片。
6. 拆分剧本为分镜。
7. 生成分镜视频提示词。
8. 生成分镜视频。
9. 合成和导出视频。

每个 AI 操作都需要显示能力名称、单次价格、批量预计总价、当前积分余额和失败退款说明。

### 5.5 任务中心

用户只能查看自己的任务，包括等待中、处理中、已完成、已失败、已取消和已退款状态。任务详情需要展示项目、生成类型、模型、参数、时间、结果和积分变化。图片、视频和合并任务优先展示生成媒体缩略图或播放器；文本任务不展示媒体缩略图，使用文本类型占位封面并显示对应能力名称。

### 5.6 积分中心

展示可用积分、冻结积分、赠送积分、充值积分、消费记录和退款记录，并提供充值入口。积分永久有效，因此不展示积分过期记录。

积分说明区域向用户解释：
- 积分获取：充值 1 元 = 10 积分，新用户注册赠送 100 积分。
- 积分扣减：发起 AI 生成任务时先冻结预计消耗积分，任务成功后正式扣除；失败、超时或取消后自动退回。
- 冻结积分：处理中任务占用的积分，任务结算后释放或扣除。
- 未到账处理：充值订单支付成功后积分自动到账，若长时间未到账可联系客服并提供订单号。

> 首版状态：用户端积分中心已展示余额、充值记录和积分说明；完整的积分流水明细页待补充。

## 6. 管理后台需求

当前管理后台按功能分为四个一级菜单：运营概览、AI 生产、账号财务、系统审计。各菜单下页面直接通过同一路由组件 `src/views/wanying/index.vue` 根据路由 key 渲染不同配置页，保持统一的列表 + 弹窗编辑交互风格。

### 6.1 用户管理

- 用户列表、手机号搜索和按账号状态筛选。
- 列表展示：用户 ID、手机号、账号状态、积分余额、冻结积分、工作区数量、创建时间。
- 启用或停用用户（调用 `/admin/users/:id/status`）。
- 手动增加或扣除积分，不设额度上限，必须填写调整原因并记录操作人（调用 `/admin/users/:id/credits`）。
- 查看用户详情、项目、任务、充值和积分流水：首版通过跳转对应列表页并自动带入用户筛选条件实现。
- 重置用户密码：首版通过后端接口 `/admin/users/:id/reset-password` 支持，页面按钮待补充。

### 6.2 企业与团队管理

管理员可以：

- 查看企业账号和团队空间。
- 查看企业所有者、成员数量和项目数量。
- 启用或禁用企业账号。
- 管理企业账号的成员和空间状态。
- 查看企业账号的积分余额、充值记录和消费明细。
- 处理企业账号的异常项目或任务。

> 首版状态：后端表结构已预留企业与团队相关字段，管理后台页面尚未独立拆分，相关数据在用户管理和任务/订单列表中通过「工作区」字段体现。

### 6.3 AI 服务配置

管理员统一维护文本、图片和视频服务，包括服务商、Base URL、API Key、模型、默认模型、备用模型、优先级、启停状态、连通性测试、超时和重试策略。

API Key 只能在后端保存和调用，不能返回给普通用户。用户只能使用管理员启用的服务和模型。

### 6.4 价格管理

价格规则可以按照能力、服务商、模型、图片尺寸、视频时长和视频分辨率区分，并支持启用、停用、生效时间和历史版本。

管理员可以随时新增、修改、启用或停用 AI 生成价格。价格修改后，新任务使用新价格；已经冻结积分的任务继续使用创建时的价格。

### 6.5 任务管理

- 查看全平台任务并按用户、项目、类型、模型和状态筛选。
- 查看任务错误信息。
- 重试失败任务、取消处理中任务（调用 `/admin/tasks/:id/retry` 和 `/admin/tasks/:id/cancel`）。
- 查看任务与积分流水的关联关系：首版通过任务行的「积分流水」字段或跳转积分流水页实现。
- 手工退款：首版在充值订单列表操作，任务列表暂不提供直接退款按钮。

### 6.6 订单管理

管理员可以查看充值订单、支付状态、到账记录和退款记录；已支付订单支持手工退款（调用 `/admin/orders/:orderNo/refund`）。订单列表支持按时间、用户、支付渠道、订单状态和金额区间筛选。

支付回调记录作为独立子页面或订单详情字段保留待实现，当前通过后端日志排查。

### 6.7 数据统计与运营看板

管理后台需要提供数据统计能力，帮助管理员判断平台增长、收入、积分消耗、AI 成本、生成质量和内容生产效率。统计看板面向平台管理员，不向普通用户开放；企业管理员只能在企业空间内查看团队自身数据。

#### 6.7.1 页面结构

首版运营看板先合并为单一「平台概览」页面，由 `/wanying/overview` 承载，原 `/wanying/analytics` 路由重定向到该页面且不在菜单显示。后续随着数据看板内容增多，再按主题拆分为独立页面。

当前「平台概览」页面结构：

| 区域 | 主要用途 |
|---|---|
| 时间筛选栏 | 今日、近 7 日、近 30 日、本月和自定义日期区间 |
| 平台累计 | 展示累计用户、工作区（含企业空间）、项目、任务、累计消耗积分、冻结积分 |
| 周期指标 | 展示统计周期内的净收入、消耗积分、生成任务数、活跃用户、预估成本、异常待处理数 |
| 经营趋势 | 收入、消耗积分、任务数、活跃用户的日趋势折线图 |
| 能力消耗排行 | 按生成环节聚合的积分消耗排行 |
| 收入与支付 | 支付渠道占比、退款金额、收入趋势 |
| 积分账务 | 积分发放与消耗类型分布 |
| 任务状态分布 | 等待中、处理中、已完成、失败、取消的任务数量 |
| AI 模型表现 | 按模型的调用量、成功率、平均耗时 |
| 失败原因 | 失败任务按错误信息聚合排行 |
| 内容生产漏斗 | 从项目创建到视频导出的阶段转化 |
| 异常监控 | 连续失败任务、支付待处理、冻结积分未释放 |
| 高消耗排行 | 高消耗用户、高消耗工作区 |
| 统计口径说明 | 指标定义和刷新频率说明 |

#### 6.7.2 通用筛选与交互

所有统计页面默认支持今日、昨日、近 7 日、近 30 日、本月、上月和自定义时间范围。数据粒度支持按小时、日、周和月切换，默认按日展示。

通用筛选维度包括：

- 账号类型：个人账号、企业空间。
- 用户维度：用户 ID、手机号、注册时间、账号状态。
- 企业维度：企业空间、企业所有者、成员规模、空间状态。
- 项目维度：项目、剧集、项目创建时间、项目状态。
- AI 维度：服务类型、服务商、模型、生成环节、图片尺寸、视频时长、视频分辨率。
- 账务维度：积分来源、积分流水类型、支付渠道、充值套餐、订单状态。
- 任务维度：任务状态、失败原因、是否重试、是否退款。

核心指标需要展示当前值、上个周期对比、变化幅度和趋势图。图表中的指标支持点击下钻到对应明细列表，例如从失败任务数跳转到任务管理并自动带入筛选条件。

#### 6.7.3 平台概览

平台概览用于展示整体经营状态，页面按「平台累计」和「周期指标」两块组织：

**平台累计指标**（不受时间筛选影响）：

| 指标 | 含义 |
|---|---|
| 累计用户 | `users` 表中的注册用户总数 |
| 工作区 | `workspaces` 表中的空间总数（个人 + 企业空间） |
| 累计项目 | `dramas` 表中的项目总数 |
| 累计任务 | `sys_task` 表中的任务总数 |
| 累计消耗积分 | 积分流水中所有扣减类记录的合计 |
| 冻结积分 | `credit_accounts.frozen` 字段合计 |

**周期指标**（受时间筛选影响）：

| 指标 | 含义 |
|---|---|
| 净收入 | 支付成功金额减去已退款金额，不包含待支付订单 |
| 消耗积分 | 统计周期内任务成功扣除的积分合计 |
| 生成任务数 | 统计周期内创建的 AI 生成任务总数 |
| 活跃用户 | 统计周期内至少发起一次生成任务的用户数 |
| 预估成本 | 首版按积分收入折算金额的 45% 估算 |
| 异常待处理 | 连续失败任务、支付待处理、冻结积分未释放的总数 |

平台概览还提供按日趋势图、能力消耗占比图、收入来源占比图、任务状态分布、AI 模型表现、失败原因排行、内容生产漏斗、异常监控列表和高消耗用户/工作区排行。

#### 6.7.4 收入与支付统计

收入统计需要展示总充值金额、净收入、支付订单数、支付成功率、客单价、退款金额、退款率、支付渠道占比和套餐占比。充值订单需要能按微信支付、支付宝、固定套餐、自定义金额、个人账号和企业空间进行拆分查看。

支付统计需要补充以下维度：

- 订单状态：待支付、支付成功、支付失败、已关闭、已退款、部分退款。
- 支付链路：下单成功率、回调成功率、重复回调次数、回调验签失败次数。
- 充值行为：首充用户数、复充用户数、首充金额、复充金额和充值间隔。
- 套餐表现：各套餐购买人数、购买次数、收入金额和退款金额。

#### 6.7.5 积分统计

积分统计需要展示积分发放、消耗、冻结、退款、手工调账和当前存量。需要区分充值积分、赠送积分和管理员手工调整积分，并支持查看各生成环节的积分消耗排行。

积分账务需要补充以下口径：

- 可用积分、冻结积分、累计充值积分、累计赠送积分、累计消耗积分。
- 任务冻结积分、成功扣除积分、失败退回积分、取消退回积分。
- 管理员手工增加积分、管理员手工扣减积分和对应调整原因。
- 用户积分余额排行、企业积分余额排行、高消耗用户排行和高消耗企业排行。
- 积分消耗分布：按生成环节、模型、项目、剧集和时间聚合。

#### 6.7.6 AI 生成与成本统计

AI 统计需要按文本、图片、视频和合并任务拆分，展示调用次数、成功次数、失败次数、成功率、平均耗时、P95 耗时、重试次数、取消次数和超时次数。

模型成本统计需要按服务商、模型、生成环节、图片尺寸、视频时长和分辨率聚合，展示预估成本、消耗积分、积分收入折算金额和毛利估算。若第三方服务无法实时返回成本，首版允许管理员在后台配置模型单位成本，用于报表估算。

AI 质量统计需要补充：

- 失败原因分布：余额不足、参数错误、第三方限流、第三方超时、内容安全拒绝、内部异常、用户取消。
- 服务商表现：调用量、成功率、失败率、平均耗时、P95 耗时、重试率和成本估算。
- 模型表现：调用量、成功率、平均成本、平均积分收入、单位毛利估算和失败排行。
- 生成环节表现：剧本改写、素材提取、提示词生成、图片生成、分镜拆解、视频提示词、视频生成、合并导出。
- 产出数量：生成图片张数、生成视频条数、生成视频总时长、合并导出次数。

#### 6.7.7 用户与企业统计

用户统计需要展示新增用户、活跃用户、付费用户、充值用户、生成用户、人均项目数、人均生成次数和人均积分消耗。企业统计需要展示企业空间数、成员数、企业充值金额、企业积分消耗、活跃企业空间和高消耗企业排行。

用户与企业统计需要补充：

- 新用户激活：注册后创建项目、发起首次生成、完成首次视频生成和首次充值。
- 付费转化：注册用户到充值用户、生成用户到充值用户、赠送积分消耗后充值用户。
- 使用深度：项目数、剧集数、任务数、图片数、视频数、导出数。
- 企业使用：成员活跃数、项目协作数、团队积分消耗、企业充值金额和企业任务成功率。
- 沉默用户：注册未创建项目、创建项目未生成、余额充足但长期未使用。

首版只要求提供基础激活和付费转化统计；精细化留存分群和 LTV 预测不纳入首版。

#### 6.7.8 内容生产漏斗

内容生产漏斗用于观察创作流程卡点，按项目和剧集统计以下阶段转化：

1. 创建项目。
2. 创建剧集或导入原始内容。
3. 完成剧本改写。
4. 完成角色、场景和道具提取。
5. 完成提示词生成。
6. 完成图片生成。
7. 完成分镜拆解。
8. 完成视频提示词生成。
9. 完成视频生成。
10. 完成合并导出。

每个阶段需要展示进入数量、完成数量、转化率、平均耗时、失败原因分布和积分消耗。漏斗支持按个人账号、企业空间、项目、剧集、生成环节和时间范围筛选。

#### 6.7.9 排行与异常监控

后台需要提供高消费用户、高消费企业、高失败率模型、高成本模型、热门生成环节、热门风格预设和失败原因排行。异常监控需要提示短时间高频生成、连续失败任务、余额异常、支付回调异常、退款异常和模型成本异常。

异常监控首版建议包含：

| 异常类型 | 触发口径 |
|---|---|
| 支付回调异常 | 回调验签失败、重复回调过多、支付成功但积分未到账 |
| 任务失败异常 | 单用户或单模型在短时间内连续失败超过阈值 |
| 成本异常 | 单模型单位成本或总成本超过后台配置阈值 |
| 积分异常 | 余额为负、冻结积分长期未释放、手工调账频率异常 |
| 退款异常 | 单用户退款次数或退款金额超过阈值 |
| 高频生成 | 单用户、单企业或单 IP 在短时间内生成次数超过阈值 |

异常列表需要展示异常类型、触发对象、触发时间、影响金额或积分、处理状态和处理人，并支持标记已处理。

#### 6.7.10 明细下钻与导出

统计图表需要支持跳转到明细数据，明细列表至少包括充值订单、积分流水、生成任务、用户、企业空间和管理员操作日志。跳转时需要保留时间范围和筛选条件。

首版至少支持导出充值订单、积分流水、生成任务、管理员操作日志和统计汇总报表。导出格式支持 CSV，后续可增加 Excel。导出任务需要记录导出人、导出时间、筛选条件、导出文件有效期和操作日志。

#### 6.7.11 数据口径与刷新频率

统计指标必须有统一口径，避免同一指标在不同页面出现不同结果。

- 累计用户：直接统计 `users` 表记录数。
- 新增用户：统计周期内 `users` 表新增的注册记录数。
- 活跃用户数：统计周期内至少发起一次生成任务的用户数量（从 `sys_task` 统计）。
- 生成用户数：统计周期内至少创建一次 AI 生成任务的用户数量。
- 付费用户数：统计周期内至少有一笔支付成功充值订单的用户数量。
- 累计项目：直接统计 `dramas` 表记录数。
- 新增项目：统计周期内 `dramas` 表新增的记录数。
- 累计工作区：直接统计 `workspaces` 表记录数。
- 新增工作区：统计周期内 `workspaces` 表新增的记录数。
- 净收入：支付成功金额减去已退款金额，不包含待支付订单。
- 积分收入折算金额：任务实际扣除积分按照 1 元 = 10 积分折算。
- 预估 AI 成本：首版按积分收入折算金额的 45% 估算；后续接入模型单位成本配置后替换为按模型真实成本估算。
- 毛利估算：积分收入折算金额减去预估 AI 成本，仅用于运营参考，不作为财务入账依据。

平台概览数据由页面刷新按钮触发实时查询；明细列表实时查询；历史统计日快照待实现。统计查询失败时不影响用户生成和充值主流程。

> 已修复问题：MySQL `only_full_group_by` 模式下 `credit_ledger` 分组排序需使用聚合函数；`UNION ALL` 多分支字段 collation 不一致导致异常监控查询报错，已改为在应用层合并排序。

## 7. 积分与计费

### 7.1 基础规则

- 1 元兑换 10 积分。
- 充值后获得对应积分。
- AI 生成消耗积分。
- 文件上传、素材管理和视频拼接首版暂不收费。
- 积分不可提现。

### 7.2 首版建议价格

以下是首版建议值，最终由管理员后台配置，不写死在前端或业务代码中。

| AI 环节 | 计价单位 | 建议价格 |
|---|---|---:|
| 剧本 AI 改写 | 每次 | 2 积分 |
| 角色/场景/道具提取 | 每次 | 2 积分 |
| 剧本拆分分镜 | 每次 | 3 积分 |
| 角色提示词生成 | 每次 | 1 积分 |
| 场景提示词生成 | 每次 | 1 积分 |
| 道具提示词生成 | 每次 | 1 积分 |
| 分镜视频提示词生成 | 每个分镜 | 1 积分 |
| 角色图片生成 | 每张 | 8 积分 |
| 场景图片生成 | 每张 | 6 积分 |
| 道具图片生成 | 每张 | 5 积分 |
| AI 视频 4 秒 | 每条 | 20 积分 |
| AI 视频 8 秒 | 每条 | 40 积分 |
| AI 视频 12 秒 | 每条 | 60 积分 |
| AI 视频 15 秒 | 每条 | 75 积分 |

视频价格还需要结合模型和分辨率进行调整，例如标准模型或 1080P 使用更高价格。

### 7.3 生成前报价

用户点击生成前，生成按钮附近直接展示单价、批量预计总价和当前余额，不再增加重复确认弹窗：

```text
生成 6 张角色图片
单价：8 积分/张
预计消耗：48 积分
当前余额：80 积分
```

余额不足时不创建任务，告知积分缺口并提供充值入口。

### 7.4 冻结、扣除和退款

推荐采用“先冻结、后结算”：

1. 创建任务前检查余额。
2. 冻结预计消耗积分。
3. 任务成功后正式扣除。
4. 任务失败、超时或取消后退回积分。
5. 批量任务按子任务分别结算。

每次积分变化都写入不可覆盖的积分流水，一个任务只能产生一次有效扣费。积分永久有效，不设置统一过期时间。

任务重试视为新的生成任务，需要重新报价并重新计费。原任务生成失败时，系统自动退还该任务冻结的全部积分。

## 8. 充值与新用户赠送

### 8.1 充值

首版提供固定充值套餐和自定义充值金额。固定套餐由管理员配置，自定义金额按照 1 元 = 10 积分实时计算，不额外赠送积分：

| 套餐 | 获得积分 | 价格 |
|---|---:|---:|
| 体验包 | 100 积分 | 10 元 |
| 创作包 | 500 积分 | 50 元 |
| 进阶包 | 1,000 积分 | 100 元 |
| 专业包 | 5,000 积分 | 500 元 |

自定义充值时，用户输入充值金额，系统按照兑换比例计算到账积分。充值不提供额外赠送积分。

充值系统需要支持创建订单、待支付、支付成功、支付失败、订单过期、退款、支付回调和重复回调幂等处理。

首版充值支持微信支付和支付宝，暂不接入 Stripe。支付渠道需要支持支付回调、签名校验、订单幂等和异常状态处理。

#### 8.1.1 支付渠道配置

管理后台「支付渠道」页将微信支付和支付宝配置分开展开：

- 微信支付卡片：启用开关 + 商户号（`wechat_mch_id`）、AppID（`wechat_app_id`）、商户证书序列号（`wechat_serial_no`）、API v3 密钥（`wechat_api_v3_key`）、商户 API 私钥（`wechat_private_key`）、微信支付平台公钥（`wechat_platform_public_key`）、Webhook 回调密钥（`wechat_webhook_secret`）。
- 支付宝卡片：启用开关 + AppID（`alipay_app_id`）、应用私钥（`alipay_private_key`）、支付宝公钥（`alipay_public_key`）、支付回跳地址（`alipay_return_url`）。
- 通用配置：支付回调地址（`payment_notify_url`）。

密钥类字段 GET 接口返回 `configured` 标记，前端不直接回显密钥原文；保存时若密钥留空且原本已配置，则回传 `configured` 让后端保持原值，避免误清空。配置页上下排版，两渠道卡片纵向堆叠。

### 8.2 新用户赠送

新用户完成手机号验证后赠送 100 积分，即价值 10 元的体验额度。赠送积分可以用于全部 AI 生成能力，包括高成本的视频生成。

- 每个账号只发放一次。
- 积分永久有效，包括充值积分和赠送积分。
- 赠送积分不能提现。
- 赠送积分固定为 100 积分，永久有效。
- 需要限制重复注册、批量注册和异常消耗。
- 赠送积分和充值积分统一按积分规则使用，可以生成高成本的视频内容。

## 9. 数据和技术改造

### 9.1 数据隔离

现有项目、剧集、角色、场景、道具、分镜、素材、生成任务和视频合成记录都需要增加所属空间归属。个人项目归属于个人工作区，企业项目归属于团队空间。后端所有查询、修改和删除操作必须校验当前用户身份、所属空间和项目权限。

### 9.2 新增核心数据

建议新增用户、登录会话、企业账号、团队空间、团队成员、项目成员权限、角色权限、积分账户、积分流水、充值订单、支付记录、价格规则、生成扣费记录、系统配置、管理员操作日志和运营统计快照等数据表。

涉及积分、订单和状态的操作必须使用数据库事务，并具备幂等键。

### 9.3 文件存储

正式对象存储使用腾讯云对象存储 COS。文件按个人工作区或企业团队空间、项目进行隔离，访问使用鉴权或临时链接，禁止通过静态 URL 访问其他用户或其他团队文件。

### 9.4 任务执行

AI 生成后续需要引入持久化任务队列和 Worker，支持重试、超时、取消、并发限制、进度持久化，以及服务重启后的恢复或明确失败。
